# AI 请求智能分析助手 — 使用说明

> 面向最终用户：如何安装扩展、在站点上抓包分析、录制流程并生成 MCP 工具，供 Cursor 等 AI 客户端直接调用站点接口。

---

## 一、产品能做什么

1. 在真实业务页面上**拦截 Fetch / XHR**，查看请求与响应
2. 用 AI **分析接口用途与字段含义**（需配置 API Key）
3. **Mock / 字段改写 / 跨环境回放**，方便联调与 UI 验证
4. 将接口一键抽象为 **MCP 工具**，由 AI IDE 通过本地助手调用
5. 调用走浏览器会话，**优先使用当前登录态**（Cookie / 页面内实时 Token），无需手抄鉴权

---

## 二、环境要求


| 要求            | 说明                                                             |
| ------------- | -------------------------------------------------------------- |
| Chrome / Edge | Manifest V3                                                    |

## 三、安装



### 3.1 加载浏览器扩展

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 开启「开发者模式」
3. 「加载已解压的扩展程序」→ 选择本仓库的 `extension` 目录
4. 记下扩展 ID（详情页地址栏或卡片上的 ID），后面注册 Native Host 可能用到



### 3.2 按站点开启扩展（重要）

**默认关闭。** 安装后不会在所有网站弹出悬浮球，也不会拦截请求。

1. 打开目标业务网站（`http` / `https`）
2. 点击浏览器工具栏上的本扩展图标
3. 当前站点开启后才会出现绿色悬浮球并开始拦截
4. 再点一次图标可关闭该站点（按 hostname 记忆，`www.a.com` 与 `a.com` 视为不同站点）

非网页地址（如 `chrome://`）无法切换，工具栏会提示当前页不可用。

### 3.3 注册 Native Messaging Host（MCP 必做）

```bash
cd extension/mcp-helper
node install.mjs 你的扩展ID
```

脚本行为摘要：


| 系统      | 行为                                                                                                                        |
| ------- | ------------------------------------------------------------------------------------------------------------------------- |
| Windows | 编译 launcher exe，写 `com.aireq.mcp_helper.json`，注册表 `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.aireq.mcp_helper` |
| macOS   | 写入 `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/`                                                    |
| Linux   | 写入 `~/.config/google-chrome/NativeMessagingHosts/`                                                                        |


**注册完成后必须完全重启浏览器。**

### 3.4 配置 AI（可选，推荐）

1. 在已开启的站点打开悬浮球 → 设置（或右键菜单「配置」）
2. 填写 API Key（OpenAI 兼容接口；默认可对接 Kimi）
3. 按需改 Base URL、Model

## 四、日常使用：请求分析与调试



### 4.1 抓包

1. 在已开启扩展的站点正常操作（登录、点菜单、提交表单）
2. 打开悬浮球面板，在「请求」列表查看记录
3. 点击行展开详情：请求头/体、响应、AI 分析入口



### 4.2 搜索与筛选

筛选条件与关键词为 **AND** 关系：

- 关键词：匹配 URL、已有 AI 分析文本
- 芯片：重复 / Mock / 已分析 等
- HTTP 方法：未勾选任一方法 = 不过滤方法
- 分组：平铺 / 按域名 / 按接口（仅影响展示）



### 4.3 多选与批量

- 行首复选框多选（点复选框不应展开详情）
- 「全选」只作用于**当前筛选结果**
- 批量条：清空、批量 AI 分析、已选 → 生成 MCP



### 4.4 Mock 与响应改写

在请求详情中配置 Mock / 高级改写规则，用于前端在不依赖后端发版时验证分支与展示。规则按站点持久化。

### 4.5 页面数据溯源 / 字段 Mock

1. 选中页面上与接口返回一致的文本
2. 点击附近 **「查来源」**
3. 在候选中选一条 JSON Path，填入新值 → **「保存字段 Mock」**
4. 刷新或重触发接口，确认仅目标字段变化

候选基于匹配算法，**不保证唯一正确**，请结合 Flow 与请求详情判断。带 **Patch** 标签表示存在字段级 patch。

### 4.6 跨环境响应回放

把正式环境真实 GET 响应「搬」到测试环境验证 UI（需已在同一浏览器登录过正式域）。

1. 设置 →「跨环境 Mock」→ 填写正式环境域名并保存
2. 请求列表行末出现「跨环境」「测试」（仅当前站点 ≠ 正式域时）
3. 「跨环境」：启用回放（可选仅下一次 / 持续）
4. 「测试」：立刻向正式域拉一次预览，不改变勾选

命中后列表显示 `ProdFetch`；正式域 401/403/超时会回退真实测试响应。仅支持 GET。

## 五、FLOW：按业务路径生成可靠工具（推荐）

当你希望 AI **稳定完成一件真实业务**时，优先用 FLOW，而不是对全站抓包一键生成。

### 5.1 录制

1. 面板进入 **「流程 / FLOW」**
2. **开始录制**，按真实业务顺序操作
3. 扩展记录用户动作，并把随后 API 归属到步骤
4. **同域新标签页**、**同 tab 整页跳转/刷新** 会自动续录（跨 hostname 不会并入同一 Flow）
5. 结束录制后，所有参与页面停止追加



### 5.2 整理与生成

1. 将请求标为「核心 / 支撑 / 噪音 / 待判定」
2. 对确认可用的请求勾选「已验证」
3. 点击「已验证生成 MCP」

生成结果会带流程来源、步骤顺序、分类与验证状态；工具测试成功/失败也会写入元数据，便于决定是否暴露给 AI。

## 六、MCP 工具



### 6.1 生成入口（勿混淆）


| 场景                | 操作                 | 说明                                            |
| ----------------- | ------------------ | --------------------------------------------- |
| 与历史行为一致、全量抓包汇总    | **一键生成 MCP 工具**    | 始终用全量 `requestRecords` + 传统生成器；**不受「增强推断」影响** |
| 当前筛选视图            | **视图内 MCP**        | 遵从「增强 MCP 推断」开关                               |
| 指定几条请求            | 勾选 → **已选 MCP**    | 同上                                            |
| 更激进的 path/body 推断 | 设置中勾选增强推断，再用视图内/已选 | 不要期望它改变「一键生成」                                 |


生成规则摘要：

- 过滤静态资源（如 `.js` / `.css` / 图片）
- 同 pathname + method（及路径模板聚类）合并为一个工具
- 命名形如 `get_api_users_list`（可在设置中选 compact 命名）



### 6.2 管理工具

打开 **「MCP 工具」** 标签：


| 操作      | 说明                                     |
| ------- | -------------------------------------- |
| 启用 / 禁用 | 禁用的工具不暴露给 MCP 客户端                      |
| 编辑      | 名称、描述、参数、required                      |
| 测试      | 走与正式调用相同的代理链                           |
| 多选合并    | 同 method + pathname 的 Schema 合并        |
| 导入 / 导出 | 支持脱敏；合并时冲突策略 skip / overwrite / rename |
| 删除      | 永久删除定义                                 |


风险标签：🟢 low（只读） / 🟠 medium（普通写） / 🔴 high（DELETE 或含高危关键词）。

### 6.3 启动 MCP Server

1. 在 MCP 工具页点击状态栏 **「启动」**
2. 状态变为「已启动 `http://127.0.0.1:9527/mcp`」（需通过 HTTP 健康检查）
3. 可用 `http://127.0.0.1:9527/health` 自检（应返回 `ok: true`）

Helper 通过 Native Messaging 连扩展，并在本地提供 Streamable HTTP MCP 服务。

### 6.4 配置 AI 客户端（Cursor 示例）

编辑 `~/.cursor/mcp.json`（Windows 多为 `%USERPROFILE%\.cursor\mcp.json`）：

```json
{
  "mcpServers": {
...其他工具
    "ai-request-analyzer": {
      "url": "http://127.0.0.1:9527/mcp"
    }
  }
}
```

注意 URL 必须包含路径 `/mcp`，端口与扩展设置一致。

### 6.5 Token 鉴权与端口（可选）

- 设置面板可配置鉴权 Token；也可由 Helper 环境变量 `MCP_AUTH_TOKEN` 控制
- 默认端口 `9527`，在设置的「MCP Server 配置」中修改后需重启 Server，并同步改客户端 URL



### 6.6 AI 调用时的登录态（必读）

- **不会使用录制时保存的 Cookie / Authorization 去操作旧账号**
- 优先：打开同站标签页，用当前浏览器会话（Cookie 或页面内实时 Token）
- Cookie 型站点：在策略允许时，无标签页也可能走 Cookie fallback
- Bearer / 页面 Token / CSRF：需要当前同站标签页；取不到实时凭据会**失败关闭**，不会静默回退录制快照
- 建议：调用前保持目标站至少一个相关标签页已登录；换账号后用新会话再调

站点亲和：不必死守录制时的精确 URL；同站主机族内打开相关页签即可，请求主机会优先用当前页签上观测到的同路径 API 主机。

## 七、工作原理（简图）

```
MCP 客户端 (Cursor 等)
    │  HTTP MCP / JSON-RPC
    ▼
MCP Helper (Node，Windows 经 exe 启动)
    │  Native Messaging
    ▼
浏览器扩展 background
    │  选页签 / 运行时鉴权
    ▼
Content Script → 页面内 fetch（当前会话）
    ▼
站点 API
```

## 八、常见问题

**Q：装了扩展但没有悬浮球？**  
A：默认按站点关闭。打开目标页后点工具栏扩展图标开启。

**Q：MCP 启动失败？**  

1. 已执行 `node install.mjs` 并重启浏览器
2. `node -v` 可用
3. Windows 检查注册表与 `com.aireq.mcp_helper.exe` 是否生成成功
4. 扩展 Service Worker 控制台是否有报错
5. 扩展 ID 是否在 Native Host `allowed_origins` 中（不符则带 ID 重装）

**Q：客户端连不上？**  

1. 面板显示「已启动」且 `/health` 正常
2. URL 含 `/mcp`，端口一致
3. Token 配置一致（若启用）

**Q：Tool not found？**  
工具已生成且启用；开关或导入后会自动同步，必要时重启 MCP Server。

**Q：调用无登录态 / 鉴权错误？**  
保持目标站标签页打开并已登录；换账号后不要依赖旧录制头。Token 型站点必须能从当前页解析到实时凭据。

**Q：换电脑后？**  
重载扩展 → 再跑 `node install.mjs` → 重启浏览器。工具定义在 `chrome.storage.local`，同浏览器配置一般仍在。

**Q：如何让工具描述更好？**  
先对请求做 AI 分析，再在 MCP 编辑器里改描述与参数说明。

## 九、配置项速查


| 配置项                        | 位置        | 默认        | 说明             |
| -------------------------- | --------- | --------- | -------------- |
| 站点扩展开关                     | 工具栏图标     | 关         | 按 hostname     |
| API Key / Base URL / Model | 设置        | Kimi 兼容默认 | AI 分析          |
| MCP 端口                     | 设置        | `9527`    | Helper 监听端口    |
| MCP Token                  | 设置 / 环境变量 | 空         | 空 = 不鉴权        |
| 启动时自动同步工具                  | 设置        | 关         | Helper 启动后同步列表 |
| 增强 MCP 推断                  | 设置        | 关         | 仅影响非「一键」入口     |
| 跨环境正式域名                    | 设置（按站点）   | 空         | 正式域回放          |
| MCP 工具命名                   | 设置        | full      | full / compact |

## 十、推荐上手路径（5 分钟）

1. 加载 `extension` → 跑 `node install.mjs` → **重启浏览器**
2. 打开业务站 → **点工具栏图标开启本站**
3. 操作几步业务 → 面板确认有请求
4. 用 FLOW 录一段关键路径 →「已验证生成 MCP」
5. 启动 MCP Server → 在 Cursor `mcp.json` 配上 `http://127.0.0.1:9527/mcp`
6. 让 AI 列出工具并调用一条只读接口验证
